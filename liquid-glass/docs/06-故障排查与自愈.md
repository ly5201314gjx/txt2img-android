# 06 · 故障排查与自愈

## 已知坑位（务必避开）

### 1. lens 特效要求圆角形状 —— `UnsupportedOperationException`

```
Only RoundedRectangularShape or CornerBasedShape is supported in lens effects
```

**原因**：`lens()` 用 SDF（有向距离场）实现，只支持圆角类形状。
`RectangleShape` 传进去直接抛异常。

**修复**：
- 直角矩形用 `RoundedCornerShape(0.dp)`（视觉相同）
- 库已加固：形状不支持时自动跳过 lens/vibrancy，只保留 blur（不会再崩）

### 2. 玻璃组件放进内容层 —— 原生级闪退

**现象**：无 Java 异常、无崩溃日志，进程直接死（渲染线程自采样递归）。

**修复**：玻璃组件（drawBackdrop）必须放 `topBar` / `overlay` 槽，见 [01-架构设计](01-架构设计.md) 铁律。

### 3. 依赖版本混搭 —— 启动即崩

backdrop 2.0.0 要求 Kotlin 2.3+ / compose 1.11+ / compileSdk 37。
参考已验证组合：**BOM 2026.06.01 + foundation 1.11.4 + material3 1.5.0-alpha23 + Kotlin 2.4.0 + AGP 9.2.1 + Gradle 9.6.1**。

### 4. 与旧 compose 混装

若项目原用 Compose 1.7/1.9，接入后全部 androidx.compose.* 会被 backdrop 的传递依赖
顶到 1.11.x——属预期，但 material3 等需同步升级。

## 崩溃自愈机制（app 侧参考实现）

```kotlin
// 1. 全局捕获 → 写 crash.log + 安全模式标志
Thread.setDefaultUncaughtExceptionHandler { _, e ->
    crashLogFile.writeText(Log.getStackTraceString(e))
    safeModeFile.writeText("1")          // 下次启动禁用玻璃
    killProcess()
}

// 2. 看门狗：启动前写 boot 标志，存活 1.2s 后删除
//    —— 原生崩溃也能被检测（boot 残留 = 上次启动即崩）

// 3. 自动分级测试（glassLevel 0→1→2）
//    崩了降级重试，活了升级重试，自动停在可用最高级
```

## 分级测试机制

| 级别 | 渲染内容 | 兼容性 |
|---|---|---|
| 0 | 只挂载层（无 drawBackdrop） | ★★★ 全设备 |
| 1 | 基础模糊（RenderEffect，API 31+） | ★★ 大部分设备 |
| 2 | 完整特效（AGSL 着色器，API 33+） | ★ 新设备 |

分级测试由应用层状态机驱动（文件标志 + 自动重启），最终稳定在设备能用的最高级。

## 远程诊断

建议 app 内置：崩溃时把 `crash.log` + 设备信息自动上传到自己的服务器，
可省去反复要日志的来回（本项目用 share.lg0304.xyz 上传实现）。

## 常见疑问

**Q：Android 13 以下能用吗？**
真玻璃渲染需要 API 33+（AGSL）。低版本自动降级：视觉玻璃（glassCard）+ Haze 传统模糊。

**Q：为什么卡片不做真玻璃？**
卡片在内容层内，做 drawBackdrop 会自采样崩溃。视觉玻璃 + 顶/底栏真玻璃已经能呈现完整液态玻璃观感（原项目同款方案）。

**Q：真玻璃和视觉玻璃怎么选？**
内容层外（顶栏/底栏/悬浮组件）→ 真玻璃；内容层内（卡片/输入框/按钮）→ 视觉玻璃。
